# Задание 04. Вопросы и ответы

Лабораторная работа 20 связана с приложением `20-01`: это Express-сервер с телефонным справочником, шаблонизатором `express-handlebars`, общим макетом страниц, частичным представлением для строк справочника, helper для кнопки «Отказаться» и статическими файлами `css`/`js`.

## 1. Шаблонизация

**Шаблонизация** - это способ формирования HTML-страниц на основе заранее подготовленных шаблонов и данных, которые передаются в эти шаблоны.

В обычном HTML все значения написаны вручную. При шаблонизации HTML содержит специальные выражения, например `{{name}}`, `{{#each entries}}`, `{{> entry-row}}`. Когда сервер обрабатывает запрос, шаблонизатор подставляет реальные данные и возвращает браузеру готовую HTML-страницу.

В лабораторной работе шаблонизация используется для вывода телефонного справочника. Например, сервер читает данные из `phonebook.json`, передает массив записей в шаблон, а Handlebars сам формирует список строк справочника.

Пример из `20-01.js`:

```js
function renderIndex(res) {
  const { entries } = readPhonebook();
  res.render('index', { entries });
}
```

Здесь `entries` - это данные, которые передаются в шаблон `index.hbs`.

## 2. Шаблон (template)

**Шаблон** - это файл или фрагмент разметки, в котором описана структура будущей HTML-страницы. В шаблоне могут быть обычные HTML-теги и специальные конструкции шаблонизатора.

В Handlebars шаблоны обычно имеют расширение `.hbs`.

В лабораторной работе есть такие шаблоны:

- `views/index.hbs` - главная форма со списком записей и кнопкой «Добавить»;
- `views/add.hbs` - форма добавления новой записи;
- `views/update.hbs` - форма изменения или удаления записи;
- `views/layouts/main.hbs` - общий макет страницы;
- `views/partials/entry-row.hbs` - частичное представление строки справочника.

Пример шаблона `index.hbs`:

```hbs
<div class="list-panel">
  {{#each entries}}
  {{> entry-row name=this.name phone=this.phone index=@index disabled=false}}
  {{/each}}
</div>
<div class="actions">
  <a class="btn-wide" href="/Add">Добавить</a>
</div>
```

Здесь шаблон перебирает массив `entries` и для каждой записи подключает partial-view `entry-row`.

## 3. Контекст шаблона (template context)

**Контекст шаблона** - это объект с данными, который сервер передает шаблону при его рендеринге.

Шаблон не получает данные сам. Он берет их из контекста. Например, если сервер передает:

```js
res.render('index', { entries });
```

то внутри `index.hbs` можно использовать переменную `entries`:

```hbs
{{#each entries}}
  {{> entry-row name=this.name phone=this.phone index=@index disabled=false}}
{{/each}}
```

В лабораторной работе в контекст шаблона передаются:

- `entries` - массив записей телефонного справочника;
- `selectedIndex` - индекс выбранной записи;
- `selectedName` - имя выбранной записи;
- `selectedPhone` - телефон выбранной записи;
- `useUpdateScript` - признак, нужно ли подключать JS-файл для формы изменения.

Пример из маршрута `GET /Update`:

```js
res.render('update', {
  entries,
  selectedIndex: index,
  selectedName: selected.name,
  selectedPhone: selected.phone,
  useUpdateScript: true,
});
```

После этого в шаблоне `update.hbs` используются значения:

```hbs
<input type="hidden" name="index" value="{{selectedIndex}}">
<input id="entry-name" type="text" name="name" value="{{selectedName}}" required>
<input id="entry-phone" type="text" name="phone" value="{{selectedPhone}}" required>
```

## 4. Макет (layout)

**Макет** - это общий шаблон страницы, в который вставляется содержимое конкретных представлений.

Макет нужен, чтобы не повторять одинаковую HTML-структуру во всех шаблонах: `DOCTYPE`, `html`, `head`, подключение CSS, общий контейнер страницы, подключение скриптов.

В лабораторной работе общий макет находится в файле `views/layouts/main.hbs`.

Пример:

```hbs
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Телефонный справочник</title>
  <link rel="stylesheet" href="/css/style.css">
</head>
<body>
  <div class="page">
    {{{body}}}
  </div>
  {{#if useUpdateScript}}
  <script src="/js/update.js"></script>
  {{/if}}
</body>
</html>
```

Главная часть здесь - `{{{body}}}`. В это место `express-handlebars` вставляет содержимое конкретного шаблона: `index.hbs`, `add.hbs` или `update.hbs`.

В `20-01.js` макет подключается так:

```js
engine({
  extname: '.hbs',
  defaultLayout: 'main',
  layoutsDir: path.join(__dirname, 'views', 'layouts'),
})
```

## 5. Частичное представление (partial-view)

**Частичное представление** - это небольшой переиспользуемый фрагмент шаблона.

Partial-view применяют, когда один и тот же HTML-блок нужен в разных местах. Вместо копирования кода создают отдельный файл и подключают его в других шаблонах.

В лабораторной работе partial-view используется для строк телефонного справочника. Файл: `views/partials/entry-row.hbs`.

Пример:

```hbs
{{#if disabled}}
<a class="entry-row disabled" href="#">
  <span class="name">{{name}}</span>
  <span class="phone">{{phone}}</span>
</a>
{{else}}
<a class="entry-row" href="/Update?index={{index}}">
  <span class="name">{{name}}</span>
  <span class="phone">{{phone}}</span>
</a>
{{/if}}
```

Этот partial-view используется в разных формах:

```hbs
{{> entry-row name=this.name phone=this.phone index=@index disabled=false}}
```

или:

```hbs
{{> entry-row name=this.name phone=this.phone disabled=true}}
```

То есть один и тот же шаблон строки может быть активной ссылкой на изменение записи или заблокированной строкой.

## 6. Хелпер (helper)

**Хелпер** - это функция, которую можно вызвать из шаблона Handlebars.

Хелперы нужны, когда внутри шаблона требуется выполнить небольшую логику: условие, цикл, форматирование данных, генерация HTML-фрагмента.

В Handlebars есть встроенные хелперы, например `if`, `each`, `with`. Также можно создавать пользовательские хелперы.

В лабораторной работе пользовательский helper используется для кнопки «Отказаться».

Пример из `20-01.js`:

```js
helpers: {
  cancelButton(href) {
    return new Handlebars.SafeString(
      `<a class="btn-wide" href="${href}">Отказаться</a>`
    );
  },
},
```

В шаблоне `add.hbs` helper вызывается так:

```hbs
{{cancelButton "/"}}
```

В результате будет создана ссылка:

```html
<a class="btn-wide" href="/">Отказаться</a>
```

## 7. Встроенные хелперы Handlebars

Основные встроенные хелперы Handlebars:

### `if`

Используется для условного вывода блока.

```hbs
{{#if useUpdateScript}}
  <script src="/js/update.js"></script>
{{/if}}
```

В лабораторной работе этот helper подключает скрипт `update.js` только для страницы изменения записи.

### `unless`

Работает как обратный `if`: выводит блок, если значение ложное.

```hbs
{{#unless entries}}
  <p>Записей нет</p>
{{/unless}}
```

### `each`

Используется для перебора массива.

```hbs
{{#each entries}}
  {{> entry-row name=this.name phone=this.phone index=@index disabled=false}}
{{/each}}
```

В лабораторной работе `each` перебирает записи телефонного справочника.

### `with`

Позволяет перейти внутрь объекта и обращаться к его свойствам напрямую.

```hbs
{{#with selected}}
  <p>{{name}} - {{phone}}</p>
{{/with}}
```

### `lookup`

Позволяет получить значение объекта или массива по динамическому ключу или индексу.

```hbs
{{lookup entries selectedIndex}}
```

### `log`

Используется для вывода отладочной информации в консоль.

```hbs
{{log entries}}
```

Также в Handlebars есть служебные механизмы вроде `helperMissing` и `blockHelperMissing`, которые используются самим шаблонизатором при обработке неизвестных helper-ов или блочных выражений. В обычной лабораторной работе чаще всего используются `if`, `unless`, `each`, `with`, `lookup`, `log`.

## 8. Статический файл

**Статический файл** - это файл, который сервер отдает клиенту без генерации на основе шаблона.

К статическим файлам относятся:

- CSS-файлы;
- JavaScript-файлы для браузера;
- изображения;
- шрифты;
- favicon;
- другие файлы, которые не нужно каждый раз формировать заново.

В лабораторной работе статические файлы находятся в папке `public`.

Примеры:

- `public/css/style.css` - стили приложения;
- `public/js/update.js` - клиентский скрипт, который блокирует кнопку «Удалить» после изменения полей.

В Express статические файлы подключаются так:

```js
app.use(express.static(path.join(__dirname, 'public')));
```

После этого файл `public/js/update.js` доступен в браузере по адресу:

```text
/js/update.js
```

А файл `public/css/style.css` - по адресу:

```text
/css/style.css
```

## 9. HTTP-заголовки Cache-Control, ETag, Last-Modified, If-Modified-Since, If-None-Match

Эти заголовки используются для кеширования HTTP-ответов. Кеширование позволяет браузеру не скачивать заново файлы, которые не изменились.

### `Cache-Control`

`Cache-Control` задает правила кеширования.

Пример:

```http
Cache-Control: public, max-age=3600
```

Это означает, что ответ можно хранить в кеше 3600 секунд.

Частые значения:

- `no-store` - не сохранять ответ в кеше;
- `no-cache` - перед использованием проверить актуальность у сервера;
- `public` - можно кешировать браузером и промежуточными кешами;
- `private` - можно кешировать только в браузере пользователя;
- `max-age=seconds` - время актуальности кеша в секундах.

Для статических файлов, например CSS и JS, кеширование особенно полезно, потому что такие файлы часто не меняются.

### `ETag`

`ETag` - это уникальный идентификатор версии ресурса.

Пример:

```http
ETag: "abc123"
```

Если файл изменится, сервер создаст другой `ETag`. Браузер может отправить старый `ETag` серверу и спросить: «У меня есть такая версия файла, она еще актуальна?».

### `Last-Modified`

`Last-Modified` показывает дату и время последнего изменения ресурса.

Пример:

```http
Last-Modified: Mon, 01 Jun 2026 10:00:00 GMT
```

Браузер может сохранить это значение и при следующем запросе проверить, изменился ли файл.

### `If-Modified-Since`

`If-Modified-Since` отправляется клиентом на сервер. В нем браузер сообщает дату версии файла, которая уже есть в кеше.

Пример:

```http
If-Modified-Since: Mon, 01 Jun 2026 10:00:00 GMT
```

Если файл после этой даты не менялся, сервер может ответить:

```http
304 Not Modified
```

Тогда браузер использует файл из кеша.

### `If-None-Match`

`If-None-Match` отправляется клиентом и содержит `ETag` версии ресурса, которая уже есть у браузера.

Пример:

```http
If-None-Match: "abc123"
```

Если текущий `ETag` на сервере такой же, сервер возвращает:

```http
304 Not Modified
```

Если ресурс изменился, сервер возвращает новый файл и новый `ETag`.

### Как это работает вместе

1. Браузер первый раз запрашивает статический файл, например `/css/style.css`.
2. Сервер отправляет файл и заголовки `ETag`, `Last-Modified`, `Cache-Control`.
3. Браузер сохраняет файл в кеше.
4. При следующем запросе браузер отправляет `If-None-Match` или `If-Modified-Since`.
5. Если файл не изменился, сервер отвечает `304 Not Modified`.
6. Если файл изменился, сервер отправляет новую версию.

## 10. Свойство `__dirname` объекта global

`__dirname` в Node.js показывает абсолютный путь к папке, где находится текущий выполняемый файл модуля.

Важно: в CommonJS-модулях `__dirname` обычно воспринимается как глобальная переменная, но технически это не обычное свойство объекта `global`, а специальная переменная, доступная внутри модуля.

В лабораторной работе `__dirname` используется для построения абсолютных путей к файлам и папкам проекта.

Пример:

```js
const DATA_FILE = path.join(__dirname, 'phonebook.json');
```

Здесь путь к `phonebook.json` строится независимо от того, из какой директории был запущен сервер.

Еще примеры:

```js
layoutsDir: path.join(__dirname, 'views', 'layouts'),
partialsDir: path.join(__dirname, 'views', 'partials'),
app.set('views', path.join(__dirname, 'views'));
app.use(express.static(path.join(__dirname, 'public')));
```

Это надежнее, чем писать относительные пути вроде `./views`, потому что абсолютный путь через `__dirname` не зависит от текущей рабочей директории процесса.

## 11. Метод `response.download()`

`response.download()` - это метод Express, который отправляет файл клиенту как скачиваемое вложение.

Обычно он используется так:

```js
app.get('/download', (req, res) => {
  res.download(path.join(__dirname, 'phonebook.json'));
});
```

Когда браузер получает такой ответ, он не просто открывает файл как обычную страницу, а предлагает скачать его.

Принцип работы:

1. Сервер получает HTTP-запрос.
2. Метод `res.download()` находит файл на диске.
3. Express устанавливает специальные HTTP-заголовки, включая `Content-Disposition: attachment`.
4. Файл отправляется клиенту.
5. Браузер начинает скачивание файла.

Можно указать имя файла, под которым он будет скачан:

```js
res.download(
  path.join(__dirname, 'phonebook.json'),
  'telephone-book.json'
);
```

Также можно передать callback для обработки ошибки:

```js
res.download(filePath, 'telephone-book.json', (err) => {
  if (err) {
    console.error('Ошибка скачивания:', err);
  }
});
```

## 12. Метод `response.attachment()`

`response.attachment()` - это метод Express, который устанавливает заголовок ответа так, чтобы браузер воспринимал содержимое как файл для скачивания.

Главное отличие:

- `res.download()` сразу отправляет конкретный файл;
- `res.attachment()` только настраивает заголовки, а содержимое нужно отправить отдельно.

Пример:

```js
app.get('/export', (req, res) => {
  res.attachment('phonebook.json');
  res.sendFile(path.join(__dirname, 'phonebook.json'));
});
```

Или так:

```js
app.get('/export-text', (req, res) => {
  res.attachment('phonebook.txt');
  res.send('Телефонный справочник');
});
```

Принцип работы:

1. `res.attachment('phonebook.txt')` устанавливает заголовок `Content-Disposition`.
2. Также Express может определить `Content-Type` по расширению файла.
3. После этого сервер отправляет содержимое через `send`, `sendFile`, `json` или другой метод.
4. Браузер воспринимает ответ как файл для скачивания.

## 13. HTTP-заголовок `Content-Disposition: attachment`

`Content-Disposition` сообщает браузеру, как обрабатывать тело HTTP-ответа.

Значение:

```http
Content-Disposition: attachment
```

означает, что содержимое нужно скачать как файл, а не открывать прямо в окне браузера.

Часто вместе с `attachment` указывают имя файла:

```http
Content-Disposition: attachment; filename="phonebook.json"
```

Тогда браузер предложит сохранить файл с именем `phonebook.json`.

Если заголовок не установлен, браузер обычно пытается открыть ресурс сам. Например, HTML откроется как страница, изображение - как картинка, текстовый файл - как текст. Если установлен `Content-Disposition: attachment`, браузер запускает скачивание.

В Express этот заголовок автоматически используется методами:

```js
res.download(filePath);
```

и:

```js
res.attachment('file.txt');
```

## Краткий итог

В лабораторной работе шаблонизация нужна для удобного формирования HTML-страниц телефонного справочника. `express-handlebars` берет шаблоны `.hbs`, получает данные из контекста и создает готовый HTML. Общий `layout` задает структуру всех страниц, `partial-view` переиспользует строку справочника, `helper` формирует кнопку «Отказаться», а статические файлы из папки `public` подключают стили и клиентский JavaScript.
